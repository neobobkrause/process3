- **Aggregate project cap:** `agents_md.rs:65` skips project loading for an untrusted project or zero byte budget. `agents_md.rs:69` initializes one remaining budget for all selected environments; `agents_md.rs:91` passes that remainder into each environment, and `agents_md.rs:99` debits loaded entry contents. Within an environment, `agents_md.rs:142` starts the remaining budget, `agents_md.rs:145` walks discovered paths in order, `agents_md.rs:146` stops when exhausted, and `agents_md.rs:161`–`185` truncates raw bytes to the remainder and debits nonblank retained data. This is a byte cap, not a token cap. The filesystem read happens before truncation (`agents_md.rs:155`), so the injection limit is not a bound on disk read size. UTF-8 loss replacement occurs after byte truncation (`agents_md.rs:175`), and separators are added later (`agents_md.rs:410`); do not describe the final assembled string as a strict byte-for-byte capped envelope.
- **Splitting does not bypass that aggregate cap:** nested documents along the selected cwd's ancestry share the same remainder (`agents_md.rs:141`–`185`), and environments also share it (`agents_md.rs:69`–`100`). A large parent can consume the budget before a child. Subdirectory files below the selected cwd are not recursively discovered: the implementation constructs only root-to-cwd ancestry (`agents_md.rs:230`–`247`). Splitting can organize scope but cannot increase the aggregate project budget in this loader.
- **Discovery and ordering:** the nearest ancestor with configured markers is found (`agents_md.rs:214`–`229`); directories are reversed into root-to-cwd order (`agents_md.rs:230`–`244`), and no root means cwd only (`agents_md.rs:245`). One candidate per directory is selected by first existing regular file (`agents_md.rs:253`–`267`), with filename order `AGENTS.override.md`, `AGENTS.md`, then configured fallbacks (`agents_md.rs:279`–`300`; constants at `agents_md.rs:43` and `45`). Host user then host thread instructions precede project entries in rendered text (`agents_md.rs:388`–`412`). These functions establish selection and textual order; they do not themselves encode a model-level conflict-resolution rule saying deeper files override higher-level instructions.
- **Loading/reloading:** manager documentation describes startup or request-boundary snapshots (`agents_md_manager.rs:65`), but caller scheduling is outside these two files. Repository rediscovery is conditional on changed environment selections, active project trust, or byte cap (`agents_md_manager.rs:90`–`96`). With unchanged keys and unchanged host instruction values, refresh returns the cached snapshot (`agents_md_manager.rs:120`–`125`). Changed host text alone reuses repository content (`agents_md_manager.rs:129`–`136`). There is no mtime/content polling in these cache keys. Thus editing AGENTS.md alone does not trigger reload on this code path. Providers are called on refresh (`agents_md_manager.rs:105`–`113`), and providers own their fetching/caching (`agents_md_manager.rs:66`). A pinned reviewer project snapshot skips discovery (`agents_md_manager.rs:129`–`130`). The cache keys shown do not directly include fallback filenames or marker configuration; broader caller lifecycle could still replace the manager.
- **Retention:** validated host instruction values and loaded content are saved in manager state/cache (`agents_md_manager.rs:149`–`157`) and returned by `get_loaded` (`agents_md_manager.rs:163`–`164`). A key change clears cache before loading, including failure/cancellation cases (`agents_md_manager.rs:93`–`96`). Subagent inheritance copies applied user/thread text and shares only opted-in thread providers (`agents_md_manager.rs:185`–`195`); inherited repository handling needs caller context. These files demonstrate retained snapshots, not guaranteed preservation in a model's attention, conversation compaction, or every inference request.
- **Host instructions differ from project-file budget:** combined text above `project_doc_max_bytes` produces a warning saying the limit applies only to project files (`agents_md_manager.rs:138`–`146`), rather than combined truncation. Host thread text has a separate 10,000 estimated-token ceiling and is rejected when oversized (`agents_md_manager.rs:200`–`211`); the bytes/token approximation implementation is not in these files. No numeric default for `project_doc_max_bytes` is established here.
